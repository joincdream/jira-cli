매우 정확한 지적입니다. 실제 Jira 프로젝트에서는 완료된 티켓이나 다른 상태의 티켓이 수십~수백 개씩 누적되기 때문에, **상태별/담당자별 필터링이 없으면 원하는 티켓을 찾기 어렵고 시각적 피로도가 급격히 높아집니다.**

따라서 **필터링 기능**을 1순위로 구현하는 것이 가장 실용적입니다. 다음과 같은 세부 구성을 제안합니다:

---

### 💡 제안: 3단계 필터링 구조

#### 1. 상태별 프리셋 탭 (Status Preset Filter)
테이블 상단에 탭 바를 두고 단축키(`1~4` 또는 `F`)로 즉시 필터링:
- **`[1: Active]` (기본값 추천)**: 할 일(To Do) + 진행 중(In Progress) + 검토(Review) 등 **완료되지 않은 미해결 티켓만 표시**
- **`[2: In Progress]`**: 현재 진행 중인 티켓만 집중
- **`[3: To Do]`**: 아직 시작하지 않은 백로그/할 일
- **`[4: Done]`**: 완료된 티켓만 모아보기
- **`[5: All]`**: 모든 티켓 (현재 상태)

> **Tip**: 기본 뷰를 `All` 대신 `Active`(미완료)로 설정해 두는 것만으로도 화면의 노이즈가 절반 이상 줄어듭니다.

#### 2. "내 티켓" 토글 (`@` 또는 `m`)
- 단축키 하나로 **"전체 티켓" ↔ "나에게 할당된 티켓(My Issues)"** 전환
- 협업 공간에서 나의 오늘 할 일만 바로 추려볼 때 매우 유용

#### 3. 슬래시(`/`) 실시간 검색 필터
- `/` 입력 시 하단에 검색 인풋 표시
- 키워드(예: `auth`, `login`, `JC-12`)를 입력하면 타이핑하는 즉시 Summary와 Key를 대상으로 실시간 필터링
- `ESC`를 누르면 검색 모드 종료 및 전체 목록 복원

---

### 🎨 예상 UI 변화 (헤더/테이블 상단)

```text
┌─ 📋 Issues (8/42) ────────────────────────────────────────────────────────┐
│ Filter: [1: Active*] [2: In Progress] [3: To Do] [4: Done] [5: All]  [@:Mine] │
├───────────────────────────────────────────────────────────────────────────┤
│ JC-102  [진행 중]  OAuth2 토큰 갱신 로직 버그 수정                                │
│ JC-105  [할 일  ]  TUI 필터링 인터페이스 설계                                    │
│ ...                                                                       │
└───────────────────────────────────────────────────────────────────────────┘
```

이 세 가지(상태 프리셋 탭, 내 티켓 토글, `/` 검색) 중 **어떤 조합이나 흐름으로 먼저 구현할지**, 혹은 추가로 고려해야 할 필터 조건(예: 라벨 필터, 기간 필터 등)이 있으신지 의견을 들려주시면 감사하겠습니다.

## 🤖 Antigravity · `2026-11-01 19:25:36` {#step-51}

사용자의 실제 사용 패턴과 Jira의 특성을 고려하여 **다중 선택(Multi-Select) 방식**과 **사전 정의 프리셋(Preset) 방식**을 비교 검토했습니다.

결론부터 말씀드리면, 사용자의 지적대로 **"Jira의 상태값은 프로젝트/팀마다 제각각(To Do, In Progress 외에 Review, QA, Blocked, Ready for Deploy 등)"**이기 때문에, 정적 프리셋 하나만으로는 한계가 분명합니다.

따라서 **다중 선택(Multi-Select) 방식이 본질적인 해결책**이며, 이를 기본으로 하되 편의성을 더한 **하이브리드 구조**를 추천합니다.

---

### 1. 두 방식의 장단점 비교

| 비교 항목 | ① 다중 선택 (Multi-Select Checkbox) | ② 고정 프리셋 (Fixed Preset Tabs) |
| :--- | :--- | :--- |
| **OR 조건 유연성** | ⭐️⭐️⭐️⭐️⭐️ **완벽함**<br>(예: `To Do OR Review`, `In Progress OR QA` 등 자유 구성) | ⭐️⭐️ **제한적**<br>(Active, In Progress 등 개발자가 정의한 고정 묶음만 지원) |
| **프로젝트 커스텀 워크플로우 호환성** | ⭐️⭐️⭐️⭐️⭐️ **완벽 호환**<br>(현재 프로젝트 이슈에 존재하는 고유 상태명을 동적으로 추출해 체크박스 제공) | ⭐️⭐️ **오작동 가능성**<br>(팀마다 다른 상태명 `Design`, `Ready for Dev` 등을 "Active"에 누락할 위험) |
| **조작 속도 (Keystrokes)** | 3~4회 키 입력 필요 (`f` 팝업 ➔ 방향키/스페이스 토글 ➔ Enter) | 1회 키 입력으로 즉시 전환 (`1`, `2` 등 숫자키) |
| **화면 공간 효율** | 팝업 모달을 사용하므로 상단 헤더 공간을 차지하지 않음 | 탭이 많아지면 터미널 가로폭이 좁을 때 잘릴 수 있음 |

---

### 2. 왜 사용자는 OR 조건을 원할까?

실무에서 개발자/엔지니어가 티켓을 볼 때 다음과 같은 복합 조회가 흔히 일어납니다:
1. **"내가 손댈 수 있는 것만":** `To Do` OR `In Progress` (Done, Review 제외)
2. **"릴리즈 직전 확인":** `Review` OR `QA` OR `Testing`
3. **"특정 상태 배제":** `Done`만 제외한 나머지 전부

이러한 요구를 고정된 `Active` 단일 탭으로 대응하면, "Review 상태도 보고 싶은데 왜 빠져있지?", "QA 상태는 왜 안 나오지?"와 같은 커스텀 워크플로우 불일치 문제가 발생합니다.

---

### 3. 권장 아키텍처: 다중 선택(Multi-Select) 기반 + 빠른 숏컷 (하이브리드)

**기본 엔진을 '동적 다중 선택(OR 조건)'으로 설계하고, 모달 내에서 원터치 프리셋을 함께 지원하는 방식**을 제안합니다.

#### 🖥️ UI 흐름 (모달 팝업: 단축키 `f`)
`f` (Filter) 키를 누르면 화면 중앙에 미니 모달이 뜹니다:

```text
┌─── 🔍 Status Filter (OR Selection) ────────────────┐
│                                                    │
│  [X] In Progress                                   │
│  [X] In Review                                     │
│  [ ] To Do                                         │
│  [ ] Done                                          │
│  [ ] Closed                                        │
│                                                    │
│  ────────────────────────────────────────────────  │
│  [Space] Toggle   [a] Select All   [u] Unresolved  │
│  [Enter] Apply    [ESC] Cancel                     │
└────────────────────────────────────────────────────┘
```

#### 동작 방식의 핵심 장점:
1. **동적 상태값 추출**: 현재 로드된 이슈들로부터 실제 존재하는 고유 상태(Status) 목록을 실시간으로 수집하여 표시하므로, 어떤 Jira 워크플로우든 100% 자동 지원.
2. **원하는 OR 조건 조합**: 스페이스바로 원하는 상태들만 체크하여 `Enter`를 누르면 즉시 해당 조건들의 OR 필터 적용.
3. **빠른 편의키 제공**:
   - `u` 키: '미해결(Unresolved)' 상태들만 일괄 체크 (Done, Closed 등 완료 상태만 해제)
   - `a` 키: 전체 선택 (All)
   - `c` 키: 전체 해제 (Clear)
4. **적용 후 테이블 타이틀 표시**:
   - `📋 Issues (12/48) [Filter: In Progress, In Review]` 형태로 현재 어떤 조건으로 걸러져 있는지 명확히 인지.
