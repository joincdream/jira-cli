# 🤖 Jira CLI Agent Guidelines

## 1. 핵심 행동 원칙 (Critical Guidelines)
1. **절대 자율 마감 금지 (Human Gatekeeper)**:
   - 에이전트는 단위 테스트를 통과했다고 해서 스스로 티켓을 완료(`jira move "완료"`)하거나, 매 턴마다 "완료할까요?"라고 보채지 마십시오.
   - 에이전트의 역할은 코드 구현, 테스트 통과 증적 수집, 코멘트 초안 작성까지입니다. 최종 티켓 마감은 반드시 **인간의 명시적 지시가 있을 때만** 수행하십시오.
2. **비대화형(Non-interactive) 호출 원칙**:
   - 무한 대기(Hang)를 유발하는 대화형 플래그를 피하고, 항상 비대화형 인자 및 정형화된 플래그를 사용하십시오.
3. **토큰 절약 우선**:
   - 티켓 조회 시 불필요한 전체 덤프 대신 `jira get <KEY> --md`를 사용하여 마크다운 서식으로 맥락을 획득하십시오.

## 2. 브리핑 표준: Agent Insight Block
사용자에게 티켓 현황을 보고할 때는 단순 데이터 나열을 금지하고, 반드시 아래의 3단 시각적 앵커 규격을 준수하십시오:

📋 [{KEY}] {요약 제목}
--------------------------------------------------------------------------------
💡 [AI 추론 & 맥락 분석]
  • 핵심 상태 및 변경점: (설명과 최신 코멘트를 종합 분석한 현재 상황 1~2줄)
  • 핵심 판단: (설계상 이슈, 제기된 피드백, 해결해야 할 핵심 과제)
  • 병목/블로커: (없음 또는 차단 요소 명시)

🎯 [추천 액션 & 실행 계획]
  1. [ ] (AI가 판단한 다음 우선순위 작업 1)
  2. [ ] (작업 2)
--------------------------------------------------------------------------------

## 3. 주요 CLI 명령어 레퍼런스
- 티켓 맥락 조회: `jira get <KEY> --md`
- 할 일 목록 조회: `jira list --status open --assignee me --md`
- 마감일 임박 티켓: `jira list --all --due <=today --md`
- 코멘트 등록: `jira comment <KEY> "<MESSAGE>"`
- 전이 가능 상태 확인: `jira transitions <KEY>`
- 상태 변경 (인간 승인 후): `jira move <KEY> "<STATUS>"`
- 웹 브라우저 토스: `jira open <KEY>`
