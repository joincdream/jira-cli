# 🤖 Jira CLI Agent Guidelines

## 1. 핵심 행동 원칙 (Critical Guidelines)
1. **사전 점검 금지 및 즉시 실행 (Fail-Fast)**:
   - `which jira`, `jira --version` 등으로 도구 설치 여부를 사전에 탐색하지 마십시오. 불필요한 사용자 승인 팝업을 발생시키지 말고 필요한 명령어를 즉시 1회 호출하십시오.
2. **원샷(1-Shot) 브리핑 및 N+1 루프 금지**:
   - 업무 파악 시 목록 조회 후 각 티켓마다 `jira get`을 반복 호출(N+1 Query)하지 마십시오.
   - 반드시 `--detail` (`-d`) 플래그를 결합하여 **단 1회 호출**로 모든 활성 티켓의 본문 설명과 최신 코멘트 맥락을 일괄 획득하십시오.
3. **실무자 멘탈 모델 기반 우선순위 추론 (Reasoning Heuristics)**:
   - "오늘 할 일"은 기계적인 `--due today` 필터가 아닙니다.
   - 1순위: 현재 **진행 중(In Progress)** 상태인 티켓 최우선 파악 (컨텍스트 스위칭 방지 및 조기 마무리).
   - 2순위: 마감일 임박도(Due Date) 및 중요도(Priority: Blocker, High) 가중치 평가.
   - 3순위: 진행 중인 작업이 없다면 `To Do` 상태 티켓 중 최적 착수 대상을 판단하여 추천.
   - 4순위: 할당된 활성 티켓이 없다면 백로그 검토 또는 신규 티켓 생성 권장.
4. **작업 수명주기(Lifecycle) 상태 전이 프로토콜**:
   - **작업 착수 시 (Task Inception)**: 사용자가 특정 티켓의 작업 착수나 계획 수립을 지시하면, 지체 없이 즉시 해당 티켓을 **'진행 중(In Progress)'**으로 전이(`jira move <KEY> "진행 중"`)하여 현재 작업 중임을 가시화하십시오.
   - **작업 마감 시 (Human Gatekeeper)**: 구현 및 테스트가 완료되었더라도 스스로 티켓을 완료(`jira move "완료"`)하지 마십시오. 최종 티켓 마감은 반드시 **인간의 명시적 지시가 있을 때만** 수행하십시오.
5. **비대화형(Non-interactive) 호출 원칙**:
   - 무한 대기를 유발하는 대화형 플래그를 피하고, 항상 비대화형 플래그와 정형화된 머신 리더블 포맷(`--md`, `--json`)을 사용하십시오.

사용자에게 티켓 현황을 보고할 때는 단순 데이터 나열을 금지하고, 반드시 아래의 3단 시각적 앵커 규격을 준수하십시오:

📋 [{KEY}] {요약 제목}

💡 [AI 추론 & 맥락 분석]
  • 핵심 상태 및 변경점: (설명과 최신 코멘트를 종합 분석한 현재 상황 1~2줄)
  • 핵심 판단: (설계상 이슈, 제기된 피드백, 해결해야 할 핵심 과제)
  • 병목/블로커: (없음 또는 차단 요소 명시)

## 3. 주요 CLI 명령어 레퍼런스
- 오늘 내 활성 업무 일괄 획득 (원샷): `jira list --assignee me --status open --detail --md`
- 내 티켓 단축 목록 조회: `jira list --mine --md`
- 특정 티켓 단독 맥락 조회: `jira get <KEY> --md`
- 티켓 담당자 지정/변경: `jira assign <KEY> <me|none|이메일|이름>`
- 사용자 및 팀원 검색: `jira users [flags] [query]`
- 마감일 임박 티켓 목록: `jira list --all --due <=today --md`
- 코멘트 등록: `jira comment <KEY> "<MESSAGE>"`
- 전이 가능 상태 확인: `jira transitions <KEY>`
- 상태 변경 (착수 시 '진행 중' 자동 전이 / 완료 시 인간 승인 후 전이): `jira move <KEY> "<STATUS>"`
- 웹 브라우저 토스: `jira open <KEY>`
