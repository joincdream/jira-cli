## 1. 개요 및 배경 (Background & Objectives)

### 1.1 배경
* 프로젝트 매니저(PM) 및 프로덕트 매니저(PdM), 테크 리드는 주간/월간 단위로 여러 프로젝트의 진척 상황을 파악하고 이해관계자에게 보고해야 합니다.
* Jira 웹 콘솔의 대시보드는 실시간 공유에는 좋지만, **"주간 회의록 작성", "Slack 공유용 텍스트 브리핑", "AI 기반 위험 요약"** 등 텍스트 중심의 신속한 리포팅 워크플로우에는 비효율적입니다.
* 또한 로컬 웹 서버(`serve`)를 띄우는 방식은 1인용 뷰어에 그치고 UI 유지보수 비용이 과다하므로, **"의사결정과 보고에 즉시 활용할 수 있는 텍스트/데이터 집계 리포팅 도구(`jira report`)"**를 구축합니다.

### 1.2 주간 리포트의 5대 핵심 구성 요소 (What to Show)
1. **Executive Summary & Health Check (거시적 요약 및 건강도)**
   * 총 대상 이슈 수, 완료율(%), 진행 중/대기 중 비중
   * **건강도(Health)**: 🟢 Normal (지연 0건) / 🟡 Warning (지연 1~2건 또는 임박 다수) / 🔴 Critical (지연 3건 이상)
2. **Key Achievements (이번 주 완료 성과)**
   * 이번 주(`resolved >= startOfWeek()`)에 완료(Done) 처리된 핵심 티켓 목록 (브리핑 1순위)
3. **Risks & Blockers (주의 및 지연 티켓 - 가장 중요)**
   * 🚨 **Overdue**: 이미 마감일이 지났는데 미해결인 티켓 (지연 일수 표시: `+3 days overdue`)
   * ⚠️ **Due Soon**: 3일 이내에 마감 예정인 티켓
4. **Workload & Resource (담당자별 리소스 분포)**
   * 담당자별 미완료 티켓 수 및 진행 상태 집계 (병목 인력/과부하 감지)
5. **Cross-Project Breakdown (다중 프로젝트 `--all` 전용)**
   * 프로젝트별 진행률, 이슈 수, 지연 건수를 비교하는 종합 표

## 2. CLI 명령어 및 플래그 사양 (Specification)

```bash
# 1. 현재 프로젝트 주간 브리핑 (기본 터미널 카드 뷰)
jira report

# 2. 전사 모든 프로젝트 횡단 주간 브리핑 (Markdown 출력 -> 클립보드/회의록용)
jira report --all --md

# 3. 특정 담당자의 주간 리포트
jira report --assignee me --md

# 4. JSON 포맷 출력 (AI 에이전트 분석용)
jira report --all --json
```

### 지원 플래그 목록

| 플래그 | 단축형 | 기본값 | 설명 |
| :--- | :--- | :--- | :--- |
| `--all` | `-A` | `false` | 현재 프로필의 프로젝트 대신 전사 모든 프로젝트를 대상으로 집계 |
| `--project` | `-p` | 현재 프로필 | 특정 프로젝트 키 지정 |
| `--assignee` | `-a` | (전체) | 특정 담당자 대상 필터 (`me` 지원) |
| `--period` | | `week` | 집계 대상 기간 (`week`, `month`, `all`) |
| `--md` | | `false` | Confluence/GitHub 호환 Markdown 포맷 출력 |
| `--json` | | `false` | 파이프라인 연계용 정형 JSON 포맷 출력 |
